# Combat Engine Plan

Last updated 2026-11-15, at commit `21532cb5`.

This file is the starting point for any session that works on the fight system. It says what is finished, what engine work is left, which decisions are waiting on the designer, and how to check a change before calling it done. The rules of the system itself are in `GAMEPLAY_MECHANICS_RULES.md`; this file only points at them.

---

## 1. Where things stand

The 2026-11 refactor had one aim: adding a spell, an enemy, an enemy caster or a test fight should be a data entry and a short script, with checks that catch a mistake.

Finished:

| Area | What it means for new work |
| --- | --- |
| Conditions by prefix (`condition_apply`, `condition_has`, `condition_end`, `condition_tick`) | Blinded works for player, enemy and ally through one set of routines. |
| Concentration (`concentration_begin`, `_end`, `_damage_check`, `_end_incapacitated`) | One spell at a time, damage saves for the player, stun ends it. |
| Assigned enemy spells (`tools/encounter_catalog.json`, `*_cast_*_override`) | A fight gives an enemy up to three spells with uses and a chance each. The enemy type owns no spells. |
| One reason per spell (`combat_why_<id>`, `combat_eval_spell_why`) | The Battle HUD shows why an option is unavailable from the same value that gates the option. |
| Sight rule (`combat_player_can_see`) | A Blinded player cannot cast a spell that needs a target they can see. Area spells are unaffected. |
| Replay guard (`pageReplayGuard` in `web/scene.js`, `combat_chain_begin` / `combat_chain_end` in `combat.txt`) | A spell inside a fight writes **no** replay lock. Step 6a removed the spell-layer locks. |
| Spell numbers from data (`spell_facts_load`, `roll_spell_damage` in `combat_spells.txt`, generated by `tools/gen_spells.js`) | Piloted on Dissonant Whispers, Burning Hands and Ray of Sickness. Their dice, type, save and upcast are written only in `tools/spell_book.json`. |
| Test tooling (`tools/play_all.js`, the scene cache in `tools/scripted_play.js`) | The whole script folder runs in about five minutes. |

What is cheap now, with the recipe in `GAMEPLAY_MECHANICS_RULES.md`:

- A damage spell that fits the shared roll: data entry, generator run, short cast label, one seeded refresh script.
- An enemy type, a template fight, and a hand-written fight with overrides.
- An enemy caster, when the spell already has its non-player effect routine.

What is **not** cheap yet is section 3.

## 2. How to work on this system

These habits each exist because something went wrong without them.

1. **Review the diff, not the report.** On 2026-11-15 a session reported a passing quicktest on a `combat.txt` that had lost its last 400 lines. Run `git diff --numstat` against the commit before the work and account for every file with deletions. Search changed files for the text `truncated for diff preview`.
2. **Last step, after the final file write:** quicktest on the fight scenes, then `git status --short` and `git diff --numstat`. `combat.txt` must still end with the `fight_orren_guards` block. Count `*label` lines before and after any write to `combat.txt` or `combat_spells.txt`.
3. **Never write tool output, a preview or a shortened copy of a file back to disk.**
4. **Any engine change is compared across the whole script folder, before and after.** The claim to aim for is "every transcript identical, or different only in line numbers", with each other difference listed and explained. "The tests pass" is a weaker claim.
5. **Use a git worktree for the old commit.** No `git stash`.
6. **Every new spell gets one play script with `"refresh": true`, `"refreshText": true` and a `"seed"`.** Without a seed the tool fixes the dice, so a re-roll on refresh cannot show.
7. **Read the new page as a player would** before reporting it done.
8. **Never build a variable name from a spell id, class or level with `{}`.** Quicktest forces the true side of every `*if`, so the name can resolve to something that does not exist. Use explicit branches; let a generator write them.
9. **`*temp` does not cross `*gosub_scene`.** A value another scene must read is a global, created in `startup_parts/` and in `mygame.js`.
10. **No `*comment` between an `*if` body and its `*elseif`.**
11. **Edit `startup_parts/`, never the built `startup.txt`.** Rebuild with `tools/build_startup.js`.
12. **A generator must not overwrite a hand edit.** Put the wording in the source data and regenerate.
13. **Banners name the state only.** No rules text or instructions on screen.
14. **A lock stays wherever a routine can be reached outside a fight.** The replay guard only runs while `combat_engaged` is true. False Life is the example: it can be cast from the stats screen.
15. **A disagreement between data and play is listed, not fixed.** The designer decides which side is right.

### The checks

Run from the repository root.

```
node tools/build_startup.js --check
node tools/gen_spell_book.js --check
node tools/gen_spells.js --check
node tools/gen_encounters.js --check

node tools/play_all.js <name parts>            only scripts whose file name contains one of these
node tools/play_all.js --out=<new folder>      the whole folder, transcripts saved
node tools/play_all.js --root=<worktree> --out=<old folder>     the same on the old commit

node quicktest.js mygame startup combat combat_spells combat_movement combat_dice combat_prose combat_ai dice_engine dev_hub equipment choicescript_stats dungeon character_stats
```

On 2026-11-16 the folder holds 1,647 scripts and all 1,647 pass (it was 1,531 of 1,645 at commit `21532cb5`; see 3.0). `node tools/play_all.js` exiting 0 is the whole check, and any failure belongs to the change being made.

## 3. Engine work still to do

In the order I would take it. Each item is one hand-off, sized to review in one sitting.

### 3.0 Clear the 114 failing play scripts (DONE 2026-11-16: 0 of 1,647 fail)

With the folder at zero, `node tools/play_all.js` exiting 0 is the whole check. What the 114 turned out to be:

- **Stale scripts, repaired** (most of them): out-of-date option names and step lists, scripts that ran past the end of a subroutine (the harness now has `"gosub": true` for those), shop scripts moved to the trade panel's settle labels, a script that forced the weather the zone system overwrites, and a refresh self-test (`lyra_paid`) that could never pass. One script (`peddler_posting_read_on`) was deleted with approval.
- **Real faults in the game, fixed:** two in `longshade_dryad.txt` (the morning counter and a line break), the Conduit Spout (jugs now fill only on the spout page, not the whole square), 17 dev-hub jump entries lost in `bfce4f22` (restored), the dev-hub fire and ice arrows granted twice on a refresh, the Chapter 5 quest count left stale until the next hub, and doubled line breaks before `fight_victory` (an ally's blow, and the end of an enemy's turn: new flag `combat_ally_break_deferred` and label `fight_victory_quiet`) and in the dev hub and Oxworth.
- **Harness faults, fixed in `scripted_play.js`:** a script starting in the same scene as the preset menu inherited the preset's page-start line, so a refresh replayed the preset; `spell_learn_result "learned" -> "known"` is now a known, expected replay difference.
- **Global rules added afterwards (2026-11-16):** dead space is now a failure for every script; the 42 that still print one carry `"allowDeadSpace": true` (grep for it to find the remaining debt; `requireNoDeadSpace` is ignored). The `weather` shortcut now pins the zone's whole day (`weather_day`, an all-day window), which the calendar used to undo on the first hub. 37 scripts that set Rain, Storm, Fog or Snow had been passing in clear weather and now run in the weather they name; all still pass.

The old table of failures at commit `21532cb5`, grouped by the first line each script reported (kept for the record):

| Count | Reason | Likely meaning |
| --- | --- | --- |
| 42 | `invalid return; we've already returned` (in `character_progression`, `combat`, `calendar`, `crafting`, `character_stats`, `equipment`, `prologue/battle_black_sinks`) | The script runs past the end of what it was written to test. Usually the script needs a last step or a stop point, not a code change. |
| about 25 | `no option matches '...'` (Cut ferns, Sell the water jug, Make Green Honey Mash, and others) | The option was renamed, moved or removed after the script was written. |
| 8 | `startup line N: ... doesn't contain` a label or scene | The script starts at a label or scene that no longer exists. |
| about 10 | `Refresh check: ... N differences` | A page that does not replay the same. Some of these may be real faults, not stale scripts. |
| 4 | `DEAD SPACE` | An empty line printed on the page. A real, small display fault. |

By area: `undead` 9, `ambrose` 9, `longshade` 8, `dev` 8, `wolves` 6, `jug` 6, `cook` 5, then smaller groups. Most are story and crafting scripts, not fight scripts.

How to do it:

1. Take one group at a time, by reason. Do not mix groups in one hand-off.
2. For each script decide one of three things: **repair the script** (the game is right), **fix the game** (the script found a real fault), or **propose deleting it** (it tests something that no longer exists).
3. Never delete a script without the designer's approval. List the proposed deletions with one line of reason each.
4. The refresh and dead-space groups come last and get the most care, because they are the ones most likely to be real faults.

Done: `node tools/play_all.js` reports 0 failed, and the counts in section 2 are updated.

### 3.1 Convert the spells that fit the shared roll as it stands

Arms of Hadar, Thunderwave, Hellish Rebuke. Each keeps its own slot spend, area loop, push and banner; only the dice loop is replaced by `roll_spell_damage`.

Done when: the three hand-written dice loops are gone and every transcript in the folder is identical.

### 3.2 Damage cantrips onto the shared roll

Fire Bolt, Ray of Frost, Eldritch Blast, Chill Touch, Vicious Mockery, Poison Spray, Shocking Grasp. They roll inside `resolve_player_hit`, which also carries Hex, Agonizing Blast (Charisma added outside the data's `add_casting_mod`) and Poisoner's Robes. Pull out one shared "spell hit" helper that keeps those three riders, then convert.

Done when: a new damage cantrip is a data entry plus an option, and every transcript is identical.

### 3.3 Healing and temporary hit points

- Cure Wounds, Healing Word: the data already loads `heal_dice`. Needs a small heal wrapper (target, minimum of 1).
- False Life, Armor of Agathys: the generator validates the temporary hit point fields but does not yet load them into `spell_fact_*`. Add the fields, then convert.

### 3.4 Weapon cantrips that scale with level

Booming Blade, True Strike. The data has `cantrip_scale` (levels 5, 11, 17) and `base_move_dice`; they are validated but not loaded. Only worth doing when characters can reach level 5.

### 3.5 Spells that stay hand-written

Magic Missile (darts shared out by the player, rolled per target), Hex, Hunter's Mark, Ensnaring Strike (riders on other attacks or on turn start), Absorb Elements (damage type comes from the triggering hit). Leave them. Their numbers should still come from `spell_facts_load` where a single number is read.

### 3.6 Older conditions onto the shared condition routines

Frightened, Restrained and Slowed still use their own fields and their own tick code. Move them onto `condition_apply` / `condition_tick` the way Blinded works. Fix on the way: ending Cause Fear or Ensnaring Strike currently clears the effect from every enemy, not only the ones that spell affected.

This must come before Web, Hold Person or any spell that restrains or paralyses.

### 3.7 The 2nd-level spell batch

Suggested order, easiest first:

1. Shatter: area, save for half. The same shape as Burning Hands and Thunderwave, so close to pure data.
2. Scorching Ray: several attack rolls from one cast. Needs a "repeat the attack" loop; decide whether each ray picks its own target.
3. After 3.6: Hold Person, Web.

Each new spell needs the Sight rule checked (does it name "a creature you can see"?), a concentration flag in the data if it has one, and a seeded refresh script.

### 3.8 Ally casters

An ally has the spell fields (`combat_ally<N>_cast_*`) but no turn step that uses them. Needs: the cast step in the ally's turn, a choice of target among enemies, and prose that does not address "you". `flavor_npc_blindness` reads the same whether the target fails or saves and speaks to the player; an ally caster needs its own lines for both outcomes.

### 3.9 Enemy casting gaps

- An enemy only casts when it is within weapon reach. A caster standing back never uses its ranged spells.
- Enemies and allies make no concentration save when damaged. Only the player does.

### 3.10 Subclasses and feats

Not yet built or tested end to end. The fight has places meant for them (for example the comment in `concentration_damage_check` where War Caster would add advantage), but nobody has proved the route. Take one subclass and one feat as pilots, and write down every place that needed a hand edit. That list is the real plan for the rest.

### 3.11 Optional: the remaining replay locks

Step 6a removed only the spell-layer locks. Still in place: dice, save, attack and last-hit locks; budget spend and grant locks; manoeuvre locks; the banner caches that exist only for replay. A new spell never writes these, so removing them makes nothing cheaper. Do it only as clean-up, one family at a time, and keep every lock that a scene outside a fight can reach (`roll_locked`, `false_life_cast_locked`, anything `choicescript_stats`, `equipment`, `dungeon` or `character_stats` calls).

## 4. Decisions waiting on the designer

Found by the step 8 audit. Play was left as it is in every case.

| # | What disagrees | Options |
| --- | --- | --- |
| 1 | An enemy's Poison Spray is an attack roll (1d12). The data, and the 2024 rule, make it a Constitution save. The player's version has the same question. | Make both a save, or record in the data that this game uses an attack roll. |
| 2 | Bane's data says medium reach. The fight applies it to every enemy at any distance. | Add the reach check, or change the data. |
| 3 | A level 3 Warlock spends a 2nd-level pact slot on Arms of Hadar, Armor of Agathys and Hellish Rebuke but gets 1st-level numbers. | Add `upcast` to the three data entries (the tabletop rule gives +1d6, +5 and +1d10), or leave as a deliberate limit. |
| 4 | Ten utility spells (Alarm, Charm Person, Comprehend Languages, Detect Magic, Disguise Self, Feather Fall, Identify, Jump, Speak with Animals, Unseen Servant) carry a `combat` entry but have no fight option. | Harmless: the entry feeds the hover card. Leave unless a card looks wrong. |
| 5 | A comment in `combat.txt` still says Poison Spray's reach is short. Data and code both say medium. | Fix the comment. |

Older open questions:

- Hellish Rebuke can only be armed while an action is left. Intended, or a leftover?
- A weapon's damage die comes from its category (finesse 1d4, ranged 1d6, two-handed 1d12, other 1d8), not from each weapon's own listed die.
- Burning Hands needs an Engaged foe to be offered.

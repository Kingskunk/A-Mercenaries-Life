*comment CLASS RESOURCES: MAXIMUMS AND LONG REST
*comment Everything a class can spend, and how much of it there is at each level, is written down HERE and nowhere else. A scene
*comment never types a pool number: every sleeping place calls calendar.txt resolve_sleep (which calls restore_class_resources), the
*comment prologue rests call restore_class_resources directly, and the panels show "x / max" from the max variables. A new pool
*comment (second-level slots, Action Surge, Arcane Recovery) is added in this section, in short_rest_preview / do_short_rest below and
*comment in the displays, and no scene that sleeps ever has to change.
*comment refresh_class_resource_maxs sets the maxima from character_class and character_level. Every line is a fixed-value set, so it
*comment is safe to repeat and needs no replay lock. update_dnd_stats calls it, so a level change followed by update_dnd_stats keeps
*comment the displays right. Each ladder sets the base value first and lets a higher level overwrite it.
*comment Second Wind follows the 2024 rules: 2 uses, 3 from level 4, 4 from level 10 (a short rest returns one, a long rest all).
*comment Rage: 2 uses, 3 from level 3, 4 from level 6, 5 from level 12, 6 from level 17. Wizard and Bard first-level slots: 2, then 3 at
*comment level 2 and 4 from level 3 (second-level slots arrive with second-level spells). Warlock Pact Magic slots: 1, then 2 from
*comment level 2, 3 from level 11, 4 from level 17.

*comment SHORT REST
*comment What a short rest gives back: a fighter regains ONE Second Wind use (2024 rules) and a warlock's Pact Magic slots all come
*comment back. short_rest_preview only reports (rest_can_gain, rest_gave); do_short_rest applies it. The caller advances the hour
*comment (advance_time) and prints the words (the dossier its own banner, the garret short_rest_banner).
*comment Replay: the warlock refill is a fixed-value set, but the fighter's use is a genuine +1. A short rest always takes an hour, so
*comment the clock at its end is unique to it: last_short_rest_stamp remembers it and a replayed page (same clock) gives nothing a
*comment second time. That needs no page_id lock, which also means a dossier round trip cannot leave a stale lock behind.
*comment Rage, Bard and Wizard slots and hit points are NOT restored: those come back with sleep, and healing stays slow.
*comment ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

*label do_short_rest
*gosub short_rest_preview
*temp sr_stamp (((campaign_day * 1440) + (clock_hour * 60)) + clock_minute)
*if ((rest_can_gain) and (not(sr_stamp = last_short_rest_stamp)))
  *if (character_class = "fighter")

  *if (character_class = "warlock")
    *set warlock_spell_slots warlock_spell_slots_max
  *set last_short_rest_stamp sr_stamp
*comment The report variables are scratch: clear them once applied, so a replay of the calling page (which would find nothing left to gain) leaves the same values behind.

*comment Training sessions: one a day, training_hours long, free, and they cannot fail. A missed day costs nothing.
*comment A training place calls training_preview on the page BEFORE (training_can_train), then advances training_hours through
*comment advance_time, then calls do_training_session, so the place never counts anything itself.
*comment "A day" is the day the session STARTED, so an evening session that runs past midnight uses that evening and not the next day.
*comment do_training_session is a genuine +1, guarded like do_short_rest: the clock at the end of a session is unique to it, so a
*comment replayed page (same clock) counts nothing a second time. last_training_day is derived from that stamp, not from campaign_day.
*label training_preview
*set training_can_train (last_training_day < campaign_day)
*return

*label do_training_session
*temp ts_end (((campaign_day * 1440) + (clock_hour * 60)) + clock_minute)
*temp ts_start (ts_end - (training_hours * 60))
*if (not(ts_end = last_training_stamp))
  *set training_sessions + 1
  *set last_training_stamp ts_end
  *set last_training_day ((ts_start - (ts_start modulo 1440)) / 1440)
*return

*comment Level up (called by the dossier page codex_levelup_do after the confirm page set level_up_from). character_level is set to an
*comment EXACT target (level_up_from + 1), not incremented, and the two things that follow are worked out from state: update_dnd_stats
*comment moves current HP by the change in max HP (so the level-up heals by that amount, as decided), and each pool rises by the change in
*comment its maximum (5e: a new slot or use is available at once). A replayed page finds the level and the maxima already changed, so it
*comment adds nothing. Class features for the new level plug in HERE, after update_dnd_stats, as one hook each; no place that
*comment levels the player up ever lists them. Only a class's own pool has a max that changes, so no class checks are needed.
*label do_level_up
*temp old_sw fighter_second_wind_max
*temp old_rage barbarian_rage_max
*temp old_pact warlock_spell_slots_max
*temp old_wiz wizard_spell_slots_max
*temp old_bard bard_spell_slots_max

*gosub_scene character_stats update_dnd_stats

*set barbarian_rage_uses (barbarian_rage_uses + (barbarian_rage_max - old_rage))
*set warlock_spell_slots (warlock_spell_slots + (warlock_spell_slots_max - old_pact))

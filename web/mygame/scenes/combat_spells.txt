*comment The dice/effect resolution for every named spell a player casts in combat (Magic Missile, Hex, Bane,
*comment Armor of Agathys, False Life, Healing Word, Dissonant Whispers) -- split out first among startup.txt's

*comment
*comment A *gosub_scene-only library scene, same treatment as combat.txt/combat_prose.txt/death.txt/equipment.txt:
*comment NOT in *scene_list, told to compile.js by its own verifyFileName("combat_spells.txt") line instead, or a
*comment compiled build silently drops it and only fails at runtime the first time a spell is cast.
*comment

*comment were already *gosub_scene startup <label> before the split, since combat.txt and startup.txt were
*comment already different files -- only the scene name changed, not the verb). Labels here that still need
*comment combat_dice.txt's own primitives (apply_outgoing_damage_resist_vuln, resolve_enemy_save) reach back the

*comment ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
*comment Up to three living enemies, front-to-back (the same order everything else in this engine already
*comment fights a group down in -- fight_pick_target, fight_check_all_dead, the initiative roll), each make a
*comment Charisma save against the player's own spell_save_dc via resolve_enemy_save above -- called directly
*comment against each target's own numbered slot (lock indices 1-6) rather than the "active target" scratch
*comment copy, since Bane's targets have no need to be the current target at all.
*comment Whichever fails is Baned for 10 rounds (1 minute at 6 seconds/round): combat_round already advances
*comment reliably once per round with its own replay lock (combat_next_turn, combat.txt), so bane_expires_round =
*comment combat_round + 9 covers exactly ten rounds inclusive of the casting round. This is a flat, deliberate
*comment stand-in for concentration -- the designer's explicit call (2026-09-27): nothing in this engine tracks
*comment concentration for any spell, and Bane isn't getting an exception. resolve_enemy_attack and resolve_enemy_
*comment save both already check it themselves (see their own Bane comments), so nothing else needs to read this
*comment label's own output.
*comment Spell-slot cost lives here, inside the same guarded block as everything else (bard_spell_slots - 1) --
*comment same reasoning as resolve_dissonant_whispers/resolve_cast_hex: putting it in the bare *choice body
*comment instead would let a Stats-screen replay double-spend it.
*label resolve_cast_bane
*if (not(combat_cast_locked)) or (not(locked_combat_cast_page_id = page_id))
  *set bard_spell_slots - 1
  *temp rcb_targeted 0
  *temp rcb_i 1
  *label resolve_cast_bane_loop
  *if (rcb_i <= combat_enemy_count) and (rcb_targeted < 3)
    *temp rcb_p (("combat_enemy" & rcb_i) & "_")
    *temp rcb_hp {(rcb_p & "hp")}
    *if (rcb_hp > 0)
      *set rcb_targeted + 1
      *gosub_scene combat_dice resolve_enemy_save rcb_p "charisma" "Charisma" rcb_i
      *if (check_success)
        *set {(rcb_p & "bane_expires_round")} (combat_round + 9)
    *set rcb_i + 1
    *goto resolve_cast_bane_loop
  *set combat_cast_locked true
  *set locked_combat_cast_page_id page_id
*return
